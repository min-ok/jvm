# Куча (`Heap`)

`Heap` — простая управляемая куча для VM: один непрерывный буфер байтов и таблица выделенных блоков. Она выдаёт «адреса» (смещения в буфере), следит за границами блоков и бросает `HeapError` при любом некорректном обращении.

- `heap.h` — объявление класса `Heap` и исключения `HeapError`.
- `heap.cpp` — реализация `alloc`, `dealloc`, `read8/64`, `write8/64`.

## Устройство

```cpp
std::vector<uint8_t>          memory;  // весь буфер, заполнен нулями
std::map<uint64_t, uint64_t>  blocks;  // начало блока -> размер в байтах
```

- Адрес — это индекс в `memory`. Указателей наружу куча не отдаёт.
- `blocks` хранит только занятые блоки и упорядочен по адресу начала. Свободное место — это промежутки между блоками и хвост буфера, отдельно оно не хранится.
- **Адрес 0 никогда не выдаётся**: поиск места начинается с 1. Поэтому 0 можно использовать как «нулевой указатель», а любое обращение по нему даёт ошибку. Полезная ёмкость кучи — `size - 1` байт.

## Singleton

```cpp
static Heap& get_heap(uint64_t size);
```

Куча существует в единственном экземпляре (статическая локальная переменная). Конструктор приватный, копирование и перемещение запрещены.

- Размер учитывается **только при первом вызове**. Все следующие вызовы `get_heap(...)` возвращают уже созданную кучу, а переданный `size` молча игнорируют.
- `size == 0` — `HeapError("uncorrect size")`. Так как исключение вылетело из инициализатора статической переменной, следующий вызов попробует создать кучу заново.
- Строка `static Heap heap = Heap(size);` компилируется только начиная с C++17 (гарантированное исключение копирования, ведь перемещение удалено).

## Выделение: `alloc(size)`

Стратегия — **first-fit**: первый подходящий промежуток слева направо.

1. `size == 0` — `HeapError("size must be > 0")`.
2. `candidate = 1`. Для каждого блока по порядку адресов:
   - свободный промежуток перед блоком: `gap = block.start - candidate`;
   - если `gap >= size`, блок размещается в `candidate` и адрес возвращается;
   - иначе `candidate = block.start + block.size` (конец текущего блока).
3. Если подходящего промежутка не нашлось, проверяется хвост: при `candidate + size > memory.size()` — `HeapError("not enough memory")`, иначе блок размещается в конце.

Возвращается адрес начала блока. Сложность — O(n) по числу блоков.

Содержимое выданного блока **не обнуляется**: при повторном использовании места в нём остаются старые данные.

## Освобождение: `dealloc(addr)`

Блок удаляется из `blocks`. Адрес должен быть **ровно началом** выделенного блока, иначе `HeapError("incorrect address")`. Это же ловит двойное освобождение и освобождение «из середины» блока. Память при этом не очищается.

## Чтение и запись

| Метод | Размер | Возврат |
|---|---|---|
| `read8` / `write8` | 1 байт | `uint8_t` |
| `read64` / `write64` | 8 байт | `int64_t` |

Все четыре метода делают одинаковые проверки по порядку:

1. **Границы буфера.** `addr >= memory.size()` или `size > memory.size() - addr` — `"incorrect address"`. Вычитание записано так, чтобы не было переполнения `addr + size`.
2. **Поиск блока.** `blocks.upper_bound(addr)` даёт первый блок с началом строго правее `addr`, затем делается шаг назад. Если шагать некуда (слева блоков нет, в том числе при `addr == 0`) — `"address is not allocated"`.
3. **Попадание в блок.** Условие `addr - start + size > block_size` — `"access beyond allocated block"`. Оно срабатывает в двух случаях: обращение выходит за конец блока и адрес лежит в свободном промежутке после блока.

Доступ не может пересекать границу блока: 8-байтовое чтение, начавшееся в одном блоке, не продолжится в соседнем, даже если блоки стоят вплотную.

Запись и чтение 64-битных значений делаются через `std::memcpy`, поэтому:

- выравнивание адреса не требуется;
- порядок байт — родной для машины (на x86/ARM это little-endian).

Методы `read*` — `const`, остальные меняют только `memory`; `blocks` они не трогают.

## Ошибки

Все ошибки — `HeapError` (наследник `std::runtime_error`):

| Сообщение | Где | Причина |
|---|---|---|
| `incorrect size` | конструктор | размер кучи 0 |
| `size must be > 0` | `alloc` | запрошен блок нулевого размера |
| `not enough memory` | `alloc` | нет места |
| `incorrect address` | `dealloc` | адрес не является началом блока |
| `incorrect address` | `read*`, `write*` | адрес или хвост доступа за пределами буфера |
| `address is not allocated` | `read*`, `write*` | слева от адреса нет ни одного блока |
| `access beyond allocated block` | `read*`, `write*` | адрес вне блока или доступ выходит за его конец |
