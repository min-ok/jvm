# Куча (`Heap`)

`Heap` — управляемая куча для VM. Программа работает с **виртуальными адресами**, а реальное положение данных в буфере знает только куча. Благодаря этому блоки можно сдвигать (уплотнять), и адреса, лежащие в регистрах и в самих данных, остаются верными. Любое некорректное обращение приводит к `HeapError`.

- `heap.h` — классы `Heap`, `BlockInfo` и исключение `HeapError`.
- `heap.cpp` — реализация `alloc`, `free`, `compress`, `new_addr`, `read8/64`, `write8/64`.

## Создание и владение

```cpp
explicit Heap(uint64_t size);
```

Куча — обычный объект: сколько экземпляров создали, столько независимых куч и получили. Всё состояние хранится в полях объекта, глобальных и статических переменных нет.

- `size` — размер реального буфера в байтах. `size == 0` — `HeapError("incorrect size")`.
- Копирование запрещено (`= delete`). Раз объявлен конструктор копирования, неявное перемещение тоже недоступно, поэтому кучу нельзя ни копировать, ни перемещать: её держат как поле или в виде объекта на месте и передают по ссылке или указателю.

## Устройство

```cpp
std::vector<uint8_t>           memory;     // реальный буфер, заполнен нулями при создании
std::map<uint64_t, BlockInfo>  blocks;     // виртуальный адрес начала -> информация о блоке
uint64_t                       next_addr;  // следующий свободный виртуальный адрес, начинается с 1
uint64_t                       offset;     // конец занятой реальной области, начинается с 0

struct BlockInfo {
    uint64_t real_addr;  // положение блока в memory
    uint64_t size;       // размер в байтах
    uint8_t  flag;       // всегда 1 (освобождённые блоки удаляются из blocks)
};
```

Два адресных пространства:

| | Виртуальные адреса | Реальные адреса |
|---|---|---|
| Кто видит | программа и VM | только куча |
| Начало | с 1 (0 никогда не выдаётся и служит «нулевым указателем») | с 0 |
| Как выдаются | счётчик `next_addr`: каждый блок получает следующие `size` адресов | блок кладётся в конец занятой области (`offset`) |
| Меняются ли | никогда | при уплотнении |

Блок с виртуальным адресом `a` и размером `n` занимает диапазон `[a, a + n)`. Внутри блока работает обычная арифметика адресов: `a + 8` указывает на второе слово. Диапазоны разных блоков не пересекаются; пока ничего не освобождали, они идут подряд, а после `free` на месте блока остаётся дырка в виртуальном пространстве.

Буфер используется целиком: реальные адреса начинаются с 0, поэтому полезный объём равен `memory.size()`.

## Выделение: `alloc(size)`

1. `size == 0` — `HeapError("size must be > 0")`.
2. Если блок не помещается (`offset + size > memory.size()`), вызывается `compress()`, и `offset` берётся из его результата.
3. Если места всё ещё не хватает — `HeapError("not enough memory")`.
4. Выдаётся новый виртуальный адрес (`new_addr(size)`), в `blocks` через `emplace` вставляется запись `{real_addr = offset, size, flag = 1}`, и `offset += size`.
5. Возвращается виртуальный адрес.

Блоки всегда кладутся в конец занятой области, поэтому `alloc` в обычном случае работает за O(log n) (вставка в `map`) без поиска места. Содержимое выданного блока не обнуляется.

## Уплотнение: `compress()`

Скользящее сжатие на месте:

1. Проход по `blocks` в порядке возрастания виртуального адреса. Начальное положение `offset = 0` (локальная переменная, не поле).
2. Для каждого блока: если его `real_addr > offset`, данные сдвигаются влево через `std::memmove` (диапазоны могут перекрываться), и в записи обновляется `real_addr`. Затем `offset += size`.
3. Освобождённых блоков в `blocks` уже нет, поэтому их место просто не попадает в результат и освобождается. (Проверка `flag` в цикле остаётся, но поскольку `flag` всегда равен 1, на результат она не влияет.)
4. Возвращается новый `offset`, то есть конец занятой области. Всё после него — один свободный кусок. `alloc` записывает результат в поле `offset`.

Виртуальные адреса при этом не меняются, поэтому снаружи уплотнение незаметно.

Пример при `memory.size() == 100`:

```
alloc(10) -> 1    real 0..9
alloc(20) -> 11   real 10..29
alloc(5)  -> 31   real 30..34
free(11)          запись блока 11 удалена из blocks, но его реальное место 10..29 пока занято
alloc(80)         не влезает (35 + 80 > 100) -> compress:
                  блок 1 остаётся на 0..9, блок 31 едет на 10..14, offset = 15
                  после этого 15 + 80 <= 100, блок выдаётся с real 15
```

### Порядок обработки

Сдвиг влево на месте безопасен, только если блоки обрабатываются по возрастанию реального адреса. Это работает, потому что порядок виртуальных адресов в `map` совпадает с порядком реальных адресов:

- блоки всегда выдаются с конца, а виртуальные адреса растут монотонно;
- уплотнение сохраняет относительный порядок блоков.

Если в будущем появится выдача блоков в «дырки», этот инвариант нужно будет пересмотреть.

## Освобождение: `free(addr)`

- Адрес должен быть ровно началом выделенного блока, иначе `HeapError("incorrect address")`. Это сообщение покрывает и неизвестный адрес (в том числе адрес из середины блока), и повторное освобождение: после первого `free` записи уже нет.
- Запись блока удаляется из `blocks` (`erase`). Реальная память освобождается при следующем уплотнении, потому что `compress` обходит только оставшиеся блоки.
- Виртуальный адрес освобождённого блока не выдаётся повторно (счётчик только растёт), поэтому позднее обращение по нему всегда оказывается ошибкой.

## Чтение и запись

| Метод | Размер | Возврат |
|---|---|---|
| `read8` / `write8` | 1 байт | `uint8_t` |
| `read64` / `write64` | 8 байт | `int64_t` |

Порядок проверок одинаков для всех четырёх:

1. **Поиск блока.** `blocks.upper_bound(addr)` даёт первый блок с началом правее `addr`; затем шаг назад. Если шагать некуда (в том числе при `addr == 0`) — `"address is not allocated"`.
2. **Блок жив?** Проверка `flag == 0` (`"use after free"`) в коде остаётся, но так как записи освобождённых блоков удаляются, она никогда не срабатывает.
3. **Границы блока.** Условие `addr - start + size > block.size` — `"access beyond allocated block"`. Оно срабатывает, когда доступ выходит за конец блока, когда адрес лежит после последнего блока и когда он попал в дырку на месте освобождённого блока (предыдущим найден чужой живой блок, и адрес за его границей). Обращение к освобождённому блоку, перед которым нет других блоков, даёт `"address is not allocated"`.
4. **Доступ.** Реальный адрес считается как `real_addr + (addr - start)`. Данные читаются и записываются через `memcpy` (для 8 байт) или напрямую (для 1 байта).

Доступ не может пересекать границу блока: 8-байтовое чтение, начавшееся в одном блоке, не продолжится в соседнем, даже если виртуальные адреса идут подряд. Выравнивание не требуется. Порядок байт родной для машины (на x86/ARM это little-endian).

Поиск блока выполняется за O(log n). Методы `read*` объявлены `const`.

## Ошибки

Все ошибки — `HeapError` (наследник `std::runtime_error`):

| Сообщение | Где | Причина |
|---|---|---|
| `incorrect size` | конструктор | размер кучи 0 |
| `size must be > 0` | `alloc` | запрошен блок нулевого размера |
| `not enough memory` | `alloc` | места нет даже после уплотнения |
| `incorrect address` | `free` | адрес не является началом блока либо блок уже освобождён |
| `address is not allocated` | `read*`, `write*` | слева от адреса нет ни одного блока |
| `access beyond allocated block` | `read*`, `write*` | доступ выходит за границы блока |

## Особенности реализации

- Записи освобождённых блоков удаляются из `blocks`, поэтому `map` содержит только живые блоки. Диагностика `use after free` поэтому не достижима: такое обращение выглядит как `access beyond allocated block` или `address is not allocated`.
- Поле `flag` в `BlockInfo` сейчас всегда равно 1 и существует как задел (например, под бит пометки сборщика мусора).
- Реальная память обнуляется только при создании кучи. Ни `alloc`, ни `free`, ни `compress` её не очищают: в новом блоке могут лежать старые данные.
- Уплотнение запускается только при нехватке места в конце буфера; других триггеров нет.
- Куча не потокобезопасна.
