# Загрузчик программ

Загрузчик читает текстовый файл программы и превращает его в `Program`, который исполняет `VM`.

- `src/loader/loader.h` — публичный API: `load_program()` и `LoadError`.
- `src/loader/loader.cpp` — парсинг: таблица опкодов, парсеры, чтение файла.

## API

```cpp
Program load_program(const std::string &path);
```

При любой ошибке бросается `LoadError` (наследник `std::runtime_error`) с номером строки: `line()` возвращает номер, а `what()` начинается с префикса `line N:`. Ошибка открытия файла имеет `line == 0`, префикса в сообщении в этом случае нет.

На выходе:

- `Program::constants` — все `CONST` в порядке появления;
- `Program::code` — инструкции, собранные через `Instruction::ABC` / `Instruction::AD`.

## Формат файла

```
# комментарий: всё после # игнорируется

CONST i 10000000000   # целая константа
CONST f 2.5           # вещественная константа

LI 1 20
ADD 3 1 2
PR 3
STP
```

Правила:

- пустые строки и строки из одних комментариев пропускаются;
- имя команды и аргументы разделяются пробелами/табами;
- меток нет: адреса переходов (`JMP`, `JZ`, `JNZ`) задаются числом;
- `CONST` — директива, а не инструкция: она не попадает в `code`;
- порядок `CONST` важен: первая константа имеет индекс 0, вторая — 1 и т.д. Именно эти индексы использует `LK`.

## Как это работает

1. Файл открывается через `std::ifstream`. Не открылся — `LoadError` с `line == 0`.
2. Построчно читается `std::getline`, счётчик строк начинается с 1.
3. Из строки отрезается всё после `#`, остаток разбирается через `std::istringstream`: первое слово — имя, остальные — аргументы.
4. Если имя `CONST` — вызывается `parse_constant`, результат кладётся в `constants`.
5. Иначе имя ищется в таблице `ops`:
   - не найдено — `unknown instruction`;
   - число аргументов не совпало с `argc` — ошибка `expects N argument(s), got M`;
   - иначе вызывается парсер, готовый `Instruction` кладётся в `code`.
6. Возвращается собранный `Program`. При ошибке функция прерывается исключением, частичный результат наружу не уходит.

## Таблица опкодов

Каждая запись связывает мнемонику с опкодом, числом аргументов и функцией-парсером:

```cpp
{"ADD", {ADD, 3, parse_regs}}
```

Парсеров несколько, по формам кодирования:

| Парсер | Форма | Инструкции |
|---|---|---|
| `parse_regs` | 0–3 регистра (`Instruction::ABC`) | `STP`, `MV`, `NEG`, `FNEG`, `I2F`, `F2I`, `IN`, `FIN`, `PR`, `FPR`, `ALLOC`, `FREE`, все арифметические операции и сравнения |
| `parse_reg_imm_s` | регистр + знаковый 21-битный imm | `LI`, `LF`, `LOAD64`, `STORE64` |
| `parse_reg_imm_u` | регистр + беззнаковый 21-битный imm | `LK`, `JZ`, `JNZ` |
| `parse_imm_u` | только беззнаковый 21-битный imm (регистр = 0) | `JMP` |

Количество аргументов по инструкциям:

| Группа | Инструкции | Аргументов |
|---|---|---|
| Управление | `STP` | 0 |
| Пересылка и загрузка | `MV` | 2 |
| | `LI`, `LF`, `LK` | 2 |
| Переходы | `JMP` | 1 |
| | `JZ`, `JNZ` | 2 |
| Целочисленная арифметика | `ADD`, `SUB`, `MUL`, `DIV`, `MOD` | 3 |
| | `NEG` | 2 |
| Вещественная арифметика | `FADD`, `FSUB`, `FMUL`, `FDIV`, `FMOD` | 3 |
| | `FNEG` | 2 |
| Преобразования | `I2F`, `F2I` | 2 |
| Сравнения | `EQ`, `LT`, `LE`, `FEQ`, `FLT`, `FLE` | 3 |
| Ввод/вывод | `IN`, `FIN`, `PR`, `FPR` | 1 |
| Память | `ALLOC` | 2 |
| | `FREE` | 1 |
| | `LOAD64`, `STORE64` | 2 (регистр, знаковый imm) |

Добавить новую инструкцию в существующей форме — одна строка в таблице.

## Проверки

- регистры: `0..28`;
- знаковый imm (`LI`, `LF`, `LOAD64`, `STORE64`): `-1048576..1048575` (21 бит со знаком);
- беззнаковый imm (`LK`, `JMP`, `JZ`, `JNZ`): `0..2097151` (21 бит);
- числа парсятся строго: хвост после числа (`12x`) — ошибка;
- `CONST`: ровно 2 аргумента, тип строго `i` или `f`; вещественное значение должно быть конечным (`inf` и `nan` отвергаются);
- `parse_regs` дополнительно отвергает более 3 аргументов.

## Ограничения и замечания

1. **`LF` принимает знаковый imm.** Кодируется как `LI`: регистр и знаковый 21-битный imm (`-1048576..1048575`), так что отрицательные значения допустимы. Загрузчик не интерпретирует imm как float, смысл поля определяет VM.
2. **`LOAD64` / `STORE64` и память.** Загрузчик кодирует их как регистр + знаковый 21-битный imm, а `ALLOC` / `FREE` — как регистровые формы. Семантика (откуда берётся адрес, проверки границ, порядок байт, поведение `FREE`) определяется VM и `docs/jvm_struct.md`, загрузчик её не проверяет.
3. **Нет проверок на уровне программы.** Загрузчик не проверяет, что адрес перехода попадает в `code` и что индекс `LK` существует в `constants`.
