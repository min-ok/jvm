# Верификатор программ

`Verifier` — статическая проверка готовой `Program` перед исполнением. Он не запускает код, а только просматривает массив инструкций и таблицу констант и собирает **все** найденные проблемы, а не останавливается на первой.

- `verifier.h` — `Verifier`, `VerifyError`, а также `Format`, `DCheck`, `OpInfo` (описание инструкции).
- `verifier.cpp` — таблица инструкций `op_table` и сами проверки.

## Место в конвейере

Загрузчик (`load_program`) проверяет текст: синтаксис, число аргументов, диапазоны регистров и непосредственных значений. Он не знает программы целиком, поэтому не может проверить то, что зависит от неё как от целого: попадает ли переход внутрь кода, существует ли константа с таким индексом, заканчивается ли программа корректно. Это делает верификатор.

```cpp
Program program = load_program(path);

Verifier verifier(program);
std::vector<VerifyError> errors = verifier.verify();

if (!errors.empty()) {
    for (const VerifyError &e : errors)
        std::cerr << "pc " << e.pc << ": " << e.message << "\n";
    // программу не запускаем
}
```

Пустой результат означает, что все проверки пройдены.

## API

```cpp
explicit Verifier(const Program &program);
std::vector<VerifyError> verify();
```

- Верификатор хранит **ссылку** на `Program`, поэтому программа должна жить дольше верификатора.
- `verify()` можно вызывать повторно: перед каждым запуском список ошибок очищается.
- Возвращается копия списка ошибок.

```cpp
struct VerifyError {
    size_t pc;            // индекс инструкции в program.code; для ошибок всей программы — 0
    std::string message;
};
```

## Порядок работы

1. `errors` очищается.
2. Для каждой инструкции по порядку (`pc = 0 … code.size()-1`) вызывается `check_instruction`.
3. После этого вызывается `check_program` — проверки всей программы.
4. Возвращается накопленный список.

Из-за такого порядка ошибки уровня программы всегда идут **после** ошибок отдельных инструкций, независимо от своего `pc`.

## Описание инструкций: `OpInfo`

Каждой инструкции в `op_table` (`unordered_map<Opcode, OpInfo>`) соответствует запись:

```cpp
struct OpInfo {
    Format format;   // Abc или Ad
    bool use_a;      // поле a используется
    bool use_b;      // поле b используется (только для Abc)
    bool use_c;      // поле c используется (только для Abc)
    DCheck d;        // как проверять поле d (только для Ad)
    bool terminal;   // инструкцией можно завершать программу
};
```

Форматы кодирования:

| `Format` | Поля | Примеры |
|---|---|---|
| `Abc` | три регистра `a`, `b`, `c` | `ADD`, `MV`, `PR`, `STP` |
| `Ad` | регистр `a` и число `d` | `LI`, `LK`, `JMP`, `JZ` |

Режимы проверки `d`:

| `DCheck` | Смысл `d` |
|---|---|
| `None` | число или смещение, проверять нечего |
| `Constant` | индекс константы |
| `Jump` | адрес перехода |

### Содержимое таблицы

| Инструкции | Формат | Используются | Проверка `d` | `terminal` |
|---|---|---|---|---|
| `STP` | Abc | — | — | да |
| `MV` | Abc | a, b | — | нет |
| `LI`, `LF` | Ad | a | `None` | нет |
| `LK` | Ad | a | `Constant` | нет |
| `JMP` | Ad | — | `Jump` | да |
| `JZ`, `JNZ` | Ad | a | `Jump` | нет |
| `ADD`, `SUB`, `MUL`, `DIV`, `MOD` | Abc | a, b, c | — | нет |
| `NEG` | Abc | a, b | — | нет |
| `FADD`, `FSUB`, `FMUL`, `FDIV` | Abc | a, b, c | — | нет |
| `FNEG` | Abc | a, b | — | нет |
| `I2F`, `F2I` | Abc | a, b | — | нет |
| `EQ`, `LT`, `LE`, `FEQ`, `FLT`, `FLE` | Abc | a, b, c | — | нет |
| `IN`, `FIN`, `PR` | Abc | a | — | нет |
| `CALL` | Ad | a | `Jump` | нет |
| `RET` | Abc | a | — | да |

Опкод, которого нет в таблице, считается неизвестным (см. ниже).

Чтобы описать новую инструкцию, достаточно добавить строку в `op_table` с нужным `OpInfo`.

## Проверки отдельной инструкции

Для каждой инструкции:

1. **Опкод известен.** Если записи в `op_table` нет — ошибка `unknown opcode`, остальные проверки для этой инструкции пропускаются.
2. **Неиспользуемые поля равны нулю** (`check_unused_fields`):
   - если `use_a == false`, то `a` должно быть 0;
   - для формата `Ad` на этом проверка полей заканчивается (`b` и `c` входят в `d`);
   - для формата `Abc` дополнительно: при `use_b == false` поле `b` равно 0, при `use_c == false` поле `c` равно 0.
3. **Поле `d`** (`check_d_field`):
   - `Constant`: `d` должно быть меньше `program.constants.size()`, иначе `there is no constant with that number`;
   - `Jump`: `d` должно быть меньше `program.code.size()`, иначе `jump target out of range`; и `d` не должно совпадать с `pc` самой инструкции, иначе `infinite loop`.

Ошибки одной инструкции накапливаются: например, у `JMP` с ненулевым `a` и целью за пределами кода будут обе.

## Проверки программы целиком

`check_program` выполняется после проверки инструкций:

1. **Программа не пуста.** Пустой `code` — `program is empty` (`pc = 0`), дальнейшие проверки пропускаются.
2. **Есть хотя бы один `STP`.** Иначе `program has no STP instruction` (`pc = 0`). Проверяется только наличие где-либо в коде, достижимость не анализируется.
3. **Последняя инструкция завершающая.** Если у неё неизвестный опкод или `terminal == false` — ошибка `last instruction must be STP/RET/JMP/JZ/JNZ`. Её `pc` — индекс последней инструкции (это единственная ошибка уровня программы с `pc`, отличным от 0).

## Таблица ошибок

| Сообщение | `pc` | Причина |
|---|---|---|
| `unknown opcode` | инструкции | опкода нет в `op_table` |
| `field 'a' must be 0` | инструкции | у инструкции не используется `a`, но оно ненулевое |
| `field 'b' must be 0` | инструкции | формат `Abc`, `b` не используется, но ненулевое |
| `field 'c' must be 0` | инструкции | формат `Abc`, `c` не используется, но ненулевое |
| `there is no constant with that number` | инструкции | индекс константы `d` вне `program.constants` |
| `jump target out of range` | инструкции | адрес перехода `d` вне `program.code` |
| `infinite loop` | инструкции | переход на саму себя (`d == pc`) |
| `program is empty` | 0 | в программе нет инструкций |
| `program has no STP instruction` | 0 | нигде нет `STP` |
| `last instruction must be STP/RET/JMP/JZ/JNZ` | последней инструкции | последняя инструкция не завершающая |

## Что верификатор не проверяет

- Номера регистров (`a`, `b`, `c`): диапазон `0..28` проверяет только загрузчик.
- Достижимость кода, циклы кроме перехода «на себя», возможность выйти из программы.
- Типы значений в регистрах (целое или вещественное), состояние памяти и кучи, глубину стека вызовов.
- Корректность операндов у инструкций, для которых `DCheck::None`: например, значение непосредственного у `LI` и `LF`.

## Особенности реализации

- Признак `terminal` у `JZ` и `JNZ` в таблице равен `false`. Поэтому программа, у которой последняя инструкция `JZ` или `JNZ`, получит ошибку, хотя текст сообщения перечисляет и их.
- Проверка `infinite loop` срабатывает на любой переход с целью на саму себя (`JMP`, `JZ`, `JNZ`, `CALL`), в том числе условный.
